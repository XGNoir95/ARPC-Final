# Homepage and Sponsors

The Content navigation starts with **Homepage**, followed by **Sponsors**. Programme, lesson, gallery, team and media management remain in their existing tabs. A programme is edited once in Programmes and referenced from Featured; featuring it does not create another programme record.

## Homepage

The page is arranged in the same order as the public homepage:

1. **Hero:** add up to eight images, reorder them and edit their captions. The image controls form the left column; headline, shared Arabic greeting and introduction form the right column. Both columns stretch to the same height, followed by the shared-caption hint and reuse control. Separate Arabic and default-wording panels are omitted. Blank image captions reuse the first completed caption. If no image captions are filled, the default wording applies. Headline and introduction fallbacks resolve independently. Existing single-image records retain their image and wording. The shared Arabic greeting appears in both image previews and is edited in the Hero settings. The overview places edit and publication controls below the image sequence without a separate greeting card. Bordered image cards sit in a three-column grid below the full-width preview. Arrow keys follow the grid, with Home and End selecting the first and last images. Longer sequences grow in the page without an internal scroll area. Unnamed images use numbered labels; image names are optional and have no preset theme. It appears below the headline on every image; a missing or blank value keeps the standard greeting. Greeting changes follow the same draft and publish workflow as the other wording.
2. **About us:** opening any card's editor provides selectors for all three cards below the website preview. Selecting a card switches the preview and editable fields together. Unsaved changes remain with each card; Save draft saves the selected card and leaves the editor open when other cards still have unsaved changes. Each save uses that card's record and revision. The image, label, heading, short introduction, expanded description, button text and destination are configurable. Older records receive the existing label/summary/button defaults until edited.
3. **Featured:** choose specific published events, webinars and courses, plus a membership announcement, in the desired order. Select up to twelve items. Membership artwork and wording can be customized here. An empty selection automatically shows up to six programmes: the closest upcoming dates first, then recently published undated programmes, then the latest past dates. The automatic list reserves space for each available programme type. Calendar dates use Asia/Dhaka. Withdrawn/deleted programmes disappear automatically; publishing a new manual selection checks that its references are still published.

Hero previews render the actual visitor navbar, Hero, Hijri date and floating controls in an isolated viewport using the same built application and stylesheet. Desktop uses 1440 by 900 and Mobile uses 390 by 844, scaled to fit the editor without changing their responsive breakpoints. Draft wording, image selection, the Arabic greeting and theme stay synchronized; slideshow autoplay is paused during editing. Draft data is sent only to the same-origin preview frame and is never placed in its URL or browser storage. Image-limit counters are omitted; Add hero image remains unavailable at the existing eight-image limit.

Only published programme wording is used in Featured previews and on the public homepage. An unpublished edit to a live programme remains private. Public programme responses include publication dates so automatic selection can rank recent content consistently.

Each homepage section retains its own draft and publish controls. Save draft does not change the public page. Editing an existing section uses its revision; concurrent changes require a refresh. New installations seed five records: Hero, three About cards and Featured. Existing installations need no migration: missing sections have defaults and are created when saved.

## Sponsors

The Sponsors tab includes a persistent desktop/mobile website preview above a three-column grid of sponsor management cards. Selecting a card reviews that draft in the public affiliations carousel; unrelated unpublished records remain private. Empty collections show that the affiliations section stays hidden until a sponsor is published. Search and publication filters remain available above the preview. Cards have equal logo, two-line name and action sections. All four actions stay on one row in this order: **Edit, Publish, Unpublish, Delete**. Actions use accessible icon buttons when a card is narrow; their text labels appear when space allows. A published unchanged entry disables Publish, and an unpublished entry disables Unpublish.

The sponsor editor groups the name, logo upload, logo proportions and completion status below a live preview. Standard and Wide preserve the artwork’s proportions on a neutral logo canvas. No description is requested or shown because sponsor records contain only the name, logo and proportions.

## Website previews

All content editors, library preview dialogs and the Homepage and Sponsors overviews use the same arrangement: the preview occupies a full-width first row, followed by a three-column card grid. Both preview modes keep the outer stage at the same width and height, with room reserved for a complete phone. Desktop fits the available preview area. Mobile displays a centered 390 by 844 phone viewport at full scale when space permits, with its full height visible inside the stage. Longer pages scroll inside the phone, accompanied by a visible scroll hint; the viewport never shortens because of panel height. It scales proportionally only when the dashboard is narrower than the phone. Card columns do not change when switching preview modes. The grid uses two columns or one column only when the dashboard itself becomes narrower. Desktop renders the real website at 1440px wide; Mobile renders at 390px wide, with the original responsive breakpoints.

Preview frames measure their full section after fonts, images, draft changes and expansions settle. Desktop fits the section into the stage; Mobile preserves a readable width and uses native vertical scrolling with a thin scrollbar. Scrolling the mobile document does not scroll the surrounding editor. Neither mode changes the outer boundary. Catalogue, Gallery and Team previews render the relevant public section without unrelated page heroes. Longer management sequences and editor fields use the enclosing page or dialog for scrolling; preview dialogs hide their scrollbar track. Preview overlays contain only the dark/light toggle; the public site retains both floating controls. Featured keeps its selection summary, three-column item grid or empty-state guidance, and bottom publication/edit controls together below the preview. Edit featured remains at the far right.

About uses the real expandable cards. Featured uses the public carousel, including membership artwork, introduction, facts and application button. Sponsors use the public affiliations carousel. Programmes can be reviewed in both the Catalogue and Programme page. Gallery previews include the real journal and photo viewer; Teams use the actual roster and profile interactions. Lesson previews share `LearningCourse` with the learner page, including published neighbouring lessons, videos and resource links. Media previews retain their image/PDF file view with the same device controls.

The selected draft replaces its published counterpart in a collection of published content. Unrelated unpublished edits remain private. Autoplay is paused for review, and preview links, forms, downloads and progress changes do not submit or navigate. Public components retain their default interaction behavior outside previews. Private media files still use the authenticated file endpoint; PDF opening remains an explicit download.

`arpc-website-preview=1` mounts an isolated renderer without live auth/content providers. Drafts and theme synchronize through same-origin, source-checked messages; drafts never enter URLs or storage. Only public content collections and the current draft are sent to the frame.

## Validation

Frontend tests cover caption fallback, automatic/date-aware and manual mixed selection, correct public application links, all About fields, draft saves, duplicate-submit protection and sponsor actions. Backend tests exercise legacy records, nested image visibility, publication references and private draft isolation. Browser checks use fictional fixtures and do not start the backend or send email.
